# Стабилизация SHOWDOWN

## CAPABILITY

Пользователь в России должен открывать сайт без VPN, входить в существующий аккаунт и пользоваться профилем, турнирами, рейтингом и административными функциями даже при кратковременных сетевых сбоях. Публичный фронтенд должен обращаться к Supabase по прямому защищённому маршруту через российский сервер.

## CONSTRAINTS

- Существующие данные пользователей, турниров, финансов и настроек сохраняются.
- База данных не пересоздаётся и не очищается.
- Перед изменениями создаются резервные копии конфигурации и базы.
- Переключение DNS выполняется только после готовности и проверки нового HTTPS-маршрута.
- Для каждого изменения должен существовать понятный откат.
- Секреты не добавляются в Git и не выводятся в отчёты.
- Публично доступны только необходимые веб-порты; PostgreSQL не публикуется в интернет.

## IMPLEMENTATION CONTRACT

### Поверхности

- Фронтенд React/Vite из GitHub.
- Продакшен-хостинг фронтенда.
- Российский сервер с self-hosted Supabase.
- DNS доменов сайта и API.

### Требуемое поведение

- Сайт и API работают через HTTPS без VPN.
- При недоступности API интерфейс завершает загрузку за ограниченное время и показывает понятную ошибку с повторной попыткой.
- После перезагрузки сервера Supabase и веб-прокси запускаются автоматически.
- Авторизация и существующие данные продолжают работать после переключения.
- DNS можно вернуть к прежним значениям в случае неуспешной проверки.

### Проверки

- Загрузка главной страницы, JS, CSS и изображений.
- Доступность API и корректный CORS с домена сайта.
- Вход существующего пользователя.
- Профиль, турниры, рейтинг и административные экраны.
- Поведение при отключённом или медленном API.
- Повторная проверка после перезагрузки сервисов.

## NON-GOALS

- Изменение дизайна и бизнес-логики сайта.
- Переписывание проекта на другой стек.
- Очистка или миграция пользовательских данных без отдельного согласования.
- Добавление новых продуктовых функций.

## OPEN QUESTIONS

- Нужен подтверждённый доступ к управлению DNS домена.
- Нужен доступ к продакшен-хостингу фронтенда либо подтверждённый способ его публикации.
- Нужно определить, где после переключения будет управляться DNS-зона: в Cloudflare без проксирования или у российского провайдера.

## HANDOFF

Спецификация готова для реализации. Следующий этап: резервные копии, проверка доступов и подготовка тестов сетевого отказа до изменения кода.
