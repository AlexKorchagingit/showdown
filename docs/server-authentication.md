# Серверная авторизация SHOWDOWN

## Источник истины

- Одноразовый код проверяет Edge Function `login-otp`; браузер не получает
  `service_role` и не обращается к таблице OTP.
- После успешного OTP GoTrue выдаёт стандартные Supabase `access_token` и
  `refresh_token`. Клиент сохраняет их через `supabase.auth.setSession()`.
- Профиль определяется только на сервере: `auth.uid()` связывается с
  `club_private.auth_links`, а роль читается из `club_private.profile_roles`.
- Email, ID профиля, `is_admin` и `user_metadata`, пришедшие от клиента, не
  участвуют в принятии решений о доступе.

## Клиент

- При запуске сначала восстанавливается Supabase-сессия, затем вызывается
  `club_current_account()`; без корректных ID, email и серверной роли интерфейс
  пользователя не открывается.
- Старые ключи `userEmail` и `showdown.userId` удаляются и больше не читаются.
  `temp_auth_email` остаётся только черновиком формы OTP и не доказывает вход.
- Realtime-подписка, профиль и административный интерфейс получают ID и роль
  только из ответа `club_current_account()`.
- Защита маршрутов в React нужна для UX, но не является границей безопасности.

## Сервер

- У `anon` нет доступа к бизнес-таблицам и RPC.
- У `authenticated` нет прямых `INSERT`, `UPDATE` или `DELETE` в public и
  `club_private`; изменения выполняются только через явные серверные команды.
- Каждая команда заново получает пользователя через `auth.uid()` и проверяет
  требуемую роль. Изменение серверной роли начинает действовать без перевыпуска JWT.
- `20260907_server_auth_contract.sql` отзывает доступ ко всем внутренним и
  случайно опубликованным функциям, после чего выдаёт `authenticated` доступ
  только к 28 разрешённым RPC. Новые функции по умолчанию остаются закрытыми.
- Миграция не меняет пользователей, роли, администраторов, балансы, финансы или
  бизнес-данные и прерывается целиком, если финальные ограничения не соблюдены.

## Проверка перед выпуском

```text
npm test
npm run typecheck:functions
npm run lint
npm run build
npm run test:security:up
npm run test:security
```

Production сначала проверяется read-only скриптом
`scripts/production-auth-audit.sql`. Миграция и фронтенд выпускаются только как
одна проверенная версия; откат не должен возвращать прямые клиентские записи или
анонимные права.
