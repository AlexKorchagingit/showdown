# Изолированная проверка авторизации SHOWDOWN

Этот контур не подключается к production. Используются искусственные профили,
локальные тестовые реквизиты и перехват отправки писем. Тестовые ключи из Compose
преднамеренно публичны и категорически не подходят для реального сервера.

## Запуск

Нужны Docker Desktop в режиме Linux containers, Node.js и установленные зависимости.

```text
npm run test:security:up
npm run test:security
npm test
npm run typecheck:functions
npm run build:local-check
npm run test:security:status
```

Шлюз: `http://127.0.0.1:55430`. PostgreSQL и Auth не публикуют собственные порты;
они находятся во внутренней сети Docker. Шлюз принимает запросы только через
loopback-публикацию. Это минимальный тестовый контур, а не полный production Supabase:
Storage, Realtime и отдельный Deno Edge Runtime здесь не развёрнуты.

Unit-тестам запрещена сеть. Интеграционные тесты допускают только этот loopback API.
Compose получает отдельный пустой `compose.env`, Vite/Vitest используют `envDir: false`.
Рабочий `.env` не загружается. `build:local-check` создаёт артефакты только с
локальными заглушками, в `dist/local-check`; публиковать их нельзя.

Скрипт SQL фиксирует локальный Docker endpoint, имя проекта и проверяет маркер
искусственной БД в той же сессии перед SQL (ON_ERROR_STOP), без второго запуска
Docker ради маркера. Команд удаления/очистки БД в скрипте нет. Каждый запуск тестов
использует новый префикс искусственных данных, не удаляя предыдущие наборы.

```text
npm run test:security:stop
```

Остановка касается только проекта `showdown-security-local`. БД хранится в `tmpfs`:
после остановки/перезапуска PostgreSQL искусственные данные исчезают. Это намеренно;
рабочих данных здесь нет. Другие Docker-проекты не затрагиваются.

## Что проверено

- Сохранение исходных IDs, трёх искусственных администраторов и балансов при миграции.
- Персональная Auth-сессия только после успешного одноразового OTP.
- Привязка прежнего профиля, согласия для нового профиля, защита от неоднозначной почты.
- Игнорирование клиентских email/userId и роли из редактируемых `user_metadata`.
- Недоступность новых привязок/ролей клиентским ролям, SuperAdmin-only смена роли.
- Серверная фильтрация приватных полей каталога, атомарное журналирование смены роли.
- Обновление токена, восстановление сессии, выход и отказ повторного использования OTP.
- HTTP-обработчик OTP исполняется под минимальным Node-адаптером `Deno.serve/env`;
  доставка письма перехватывается, но Auth, SQL и PostgREST настоящие локальные.
- Серверные счета/билеты и оплата: отказ anon/обычному пользователю, неизменяемые
  клиентом тариф/автор/дата, повторные и конкурентные запросы, полная проверка
  пакета счетов до оплаты, атомарный откат при искусственно вызванном сбое журнала.
- Отмена счетов/билетов без удаления исходной строки: обязательная причина,
  неизменяемый снимок, автор и дата, атомарный журнал, конкурентная отмена/оплата,
  запрет оплаты всего пакета при наличии отменённой записи. Отмена не является возвратом денег.
- Unit-набор на этапе 2.2e: 103 теста, включая восстановление UUID финансового запроса
  после перезагрузки той же вкладки, изоляцию администраторов и отказ при повреждённом
  или недоступном хранилище, защиту от запоздалых ответов после отмены, исключение
  отмен из итогов и безопасный CSV-экспорт. Интеграционный набор 2.2e: 74 проверки, включая
  часы зарегистрированных дилеров до первого счёта, повторы и параллельные изменения,
  сохранение дат оплаты, откат при сбое журнала, фильтрацию кассы/причин отмены по роли
  и сохранение истории отмен при повторном применении миграций.
  TypeScript и локальная сборка проходят.
  Финансовая миграция не меняет старые суммы/даты/профили.
  Полный UI в браузере и на физических Android/iPhone для этого подэтапа ещё не проверен.
- Персонал: сохранение исходных JSON-массивов, одинаковых имён и пустых слотов,
  отдельные UUID без привязки по имени, закрытые таблицы/вспомогательные функции,
  отказ anon/обычному пользователю/отозванному администратору, сохранение полномочий
  SuperAdmin, фильтрация снимка по роли, запрет подмены автора/времени/полей операции.
- Персонал: одновременные изменения двух администраторов, повтор добавления и
  уменьшения нулевых часов, конфликт старого комментария, архив без удаления,
  запрет изменения архивной и чужой записи, атомарный откат при сбое журнала,
  первоначальная обработка нового турнира, повтор миграции, отказ на неожиданном
  формате старого JSON без частичной миграции. Модульные проверки также покрывают
  UUID после перезагрузки, ревизии, запрет общего сохранения кадровых полей и
  отсутствие автоматического объединения часов по имени.
- Магазин/бонусы: совпадение серверного каталога с существующими ценами и типами,
  собственный снимок кошелька, закрытые вспомогательные объекты, отказ anon и
  заблокированному аккаунту, отказ подменённым цене/балансу/автору/владельцу/дате.
  Повторы покупки с одним и разными UUID не списывают стоимость дважды; разные
  покупки на один остаток не уводят его в минус. Выбор платного предмета требует
  владения; старый повтор не возвращает прошлый внешний вид. Изменение цены
  требует новой ревизии, повтор миграции не сбрасывает каталог.
- Одноразовый бонус: исходная запись сохраняется, другие уведомления не теряются,
  чужой бонус недоступен, покупка одновременно с бонусом не теряет сумму. Проверены
  отрицательные/дробные суммы, переполнение, одинаковые ID уведомлений, откат всех
  частей операции при сбое журнала и сохранение пользователей/администраторов.
  Модульные тесты покрывают проверку подтверждений, отдельные ревизии каталога и
  кошелька, серверные цены в UI и восстановление UUID магазина в той же вкладке.
- Закрытие турнира: сервер сам рассчитывает рейтинг и рубины по полному набору
  мест, атомарно фиксирует участников, кошельки, флаги и аудит. Проверены User/Admin/
  SuperAdmin, закрытые квитанции и функции, повторы/параллельные запросы, подмена
  результатов и сумм, повтор UUID с другими параметрами и полный откат при сбое
  журнала. Целевой набор: 5/5; полный интеграционный набор: 105/105; модульный:
  110/110.
- Профиль/ACL: сервер принимает только собственные никнейм, дату рождения и слоган;
  параллельные изменения разных полей не теряются. `NULL`, неверные типы/длины/даты,
  целевой user ID и поля роли, email, баланса, уведомлений и инвентаря отклоняются.
  Прямой `UPDATE users` запрещён User/Admin/SuperAdmin, при этом серверные команды
  профиля, ролей и начислений продолжают работать. Целевой набор: 6/6; полный
  интеграционный набор: 111/111; модульный: 110/110.

## Ограничение этапа

Checkpoint 2.3a: локальная миграция `20260904_anon_access.sql` закрывает анонимный
доступ к объектам `public`, включая PUBLIC/column/default ACL и функции. Все 23
новых интеграционных теста прошли отдельно за 90.48 секунды: CRUD/upsert,
вложенные связи, views, SECURITY DEFINER, прямой SQL/TRUNCATE/sequence, будущие
объекты, откат при унаследованных правах, повтор bootstrap, сохранность данных
и администраторов, OTP/Auth, регистрация, refresh, магазин и касса.
Unit-набор вырос до 110 успешно пройденных тестов, включая 7 проверок безопасной
обвязки SQL без запуска Docker. Полный интеграционный набор: 97 из 97 тестов
прошли за 181.09 секунды после отделения синхронной подготовки фикстур от сетевых
Auth-запросов; рабочий 10-секундный таймаут входа не увеличивался.

Checkpoint 2.3b: `20260904_authenticated_policies.sql` заменяет все открытые
`FOR ALL USING (true)` правила на политики по подтверждённой учётной записи и роли.
Полный набор после применения: 97/97; целевой anon/RLS-набор: 24/24. Прямые
защищённые записи администратора ещё закрываются следующим этапом, поэтому эту
промежуточную версию отдельно в production не применять.

Миграции `20260903_auth_foundation.sql`, `20260903_finance_commands.sql`,
`20260903_registered_dealer_hours.sql`, `20260903_transaction_voids.sql` — промежуточные
этапы; применять в этом порядке в локальном контуре, затем `20260903_personnel_commands.sql`
и `20260903_wallet_shop.sql`, затем `20260904_anon_access.sql`,
`20260904_authenticated_policies.sql`, `20260904_ruby_grants.sql` и
`20260904_tournament_closure.sql`, затем `20260904_profile_updates.sql` и
`20260904_user_update_acl.sql`.
Anon закрыт, открытые TRUE-политики заменены, административные начисления, полное
закрытие турнира и собственный профиль переведены на сервер. Остаются остальные
операции турнира/участников, прямой журнал, таймер и отзыв оставшихся
широких authenticated ACL. Прямой `UPDATE users` уже закрыт. Не применять
промежуточную версию к рабочей базе и не
публиковать новый клиент без согласованного полного переключения.
